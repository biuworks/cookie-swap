# 账号快照

在同一个网站上保存多份登录态，需要时一键换号 —— 不用退出登录，也不用重新输密码。

浏览器扩展（Manifest V3），当前版本 `0.2.0`，需要 Chrome 106 或更新版本。

---

## 它解决什么问题

很多网站不允许同一个浏览器同时登录多个账号，换个号就得退出、重新登录、重新过验证码。来回切几次，人先崩了。

这个扩展把「当前页面的登录态」整份存下来（Cookie ＋ localStorage ＋ sessionStorage），之后就能在不同的已保存账号之间直接切换。快照只存在你自己的浏览器里。

---

## 安装

目前没有上架扩展商店，用「加载已解压的扩展程序」安装：

1. 下载或克隆这个仓库
2. 打开 `chrome://extensions`
3. 右上角打开「开发者模式」
4. 点「加载已解压的扩展程序」，选择仓库根目录（含 `manifest.json` 的那一层）

装好后工具栏会出现图标，点开就是弹窗。

---

## 怎么用

**第一次用**：先用浏览器正常登录目标网站，然后打开扩展弹窗 → 点「保存当前登录」→ 起个名字（比如「工作号」）→ 保存。

**再加一个账号**：点「换个号」把当前页面变成未登录，正常登录另一个账号，再点「保存当前登录」。

**切换**：点某个账号旁边的「切换」，页面会刷新成那个账号的登录态。

**更新快照**：GitHub、B站、X/Twitter 的账号标识与已绑定快照一致、认证 Cookie 完整时，会自动保存会话轮换。你也可以点击底栏「更新」。身份不同或认证字段缺失时停止自动更新。

**无法识别的网站**：默认「另存为新账号」。若已有明确绑定的快照，可以点击「确认更新」，核对当前仍是同一账号后只更新一次，自动更新继续关闭。同名另存会提示改名，不能静默覆盖。

**保护备份**：首次保存同时生成一份固定备份，普通更新不会替换它。账号菜单里的「撤销上次更新」恢复上一版；「恢复保护备份」恢复固定备份。这两种恢复只改变保存的快照，并暂停自动更新；点击「切换」才应用到网页。需要替换固定备份时，单独选择「更新保护备份」并确认。

**删错了**：删除后有 6 秒可以点「撤销」。

## 界面上的几个设计决定

弹窗分成「**正在使用**」和「**可切换**」两段：前者是状态，后者是选项，两者本来就不该长得一样。

- **底栏主按钮跟着状态变。** 当前登录态已经存过了，就不该再显示「保存当前登录」——那只会造出一份同一会话的副本。这时按钮变成「更新「xxx」」。只有页面登录着、但没有任何快照与之匹配时，才显示「保存当前登录」。
- **当前账号和上次绑定分开。** 无法确认身份时不显示「使用中」。底栏「更新」由后台重新核对账号；未知身份的一次确认绑定目标快照、页面及完整采集内容，变化或后台重启后需要重新确认。
- **凭证过期才会出现在卡片上。** 快照里的 Cookie 有过期的，副标题会标出来并可点开看详情；正常情况那里只有一行时间。Cookie 数量这类统计只在保存成功的那一条提示里出现一次。
- **安全说明不常驻。** 首次安装完整讲一遍，之后随时点右上角 ⓘ 查看；「切换会刷新页面、未提交的内容会丢」这条只在页面真的有未提交内容时才拦你一次。

## 权限说明

| 权限 | 用来做什么 |
|---|---|
| `cookies` | 读写 Cookie —— 这是保存和恢复登录态的核心 |
| `storage` | 把快照存在浏览器本地（`chrome.storage.local`） |
| `tabs` | 读取当前标签页地址、切换后刷新或跳转到对应的页面 |
| `scripting` | 在页面里读写 localStorage / sessionStorage；切换前检查有没有未提交的表单 |
| `unlimitedStorage` | 单份快照上限 8MB，多份加起来可能超过 `chrome.storage.local` 的默认配额 |
| `host_permissions: http/https` | 上面这些操作需要在任意网站上执行 |

**没有远程服务器，没有任何数据上传。** 唯一的网络请求是页面自身的刷新与跳转。

## 实现要点

```
manifest.json
src/
  background.js       service worker：所有实际操作的入口
  refresh-service.js  串行更新、来源文档、一次确认、备份与暂停状态
  refresh.js          站点身份规则、代次、快照版本及动态脚本注册
  page-hide.js        页面隐藏/离开时的幂等 Web Storage 监听
  popup.html/.css/.js 弹窗界面
  cookies.js          Cookie 快照、身份比对、过期计算
  profiles.js         快照索引、命名、删除撤销、当前账号判定
  page-storage.js     注入页面执行的三个函数（读存储 / 写存储 / 查未提交表单）
  domain.js           站点识别（可注册域名）
  swap.js             切换流程编排（写 Cookie → 必要时跳转 → 写存储 → 刷新）
  format.js           面向用户的文案
  blank-document.js   清空登录态时临时注入的内容脚本
tests/                node:test，包括后台、弹窗和安全回归
scripts/browser-acceptance.mjs  隔离 Chrome 真实 API 验收
```

几个值得说明的地方：

- **快照分开保存**：索引 `profiles`、正文及上一版 `capture:<id>`、独立保护备份 `protectedBackup:<id>`。每个版本上限 8MB。更新正文、索引、绑定与首次备份使用同一次本地存储提交。
- **索引里确实含有登录凭证的值。** 判断「当前页面登录的是哪个已保存账号」需要按 Cookie 的值去做比对，所以索引记录里额外存了一份 `identity`（名字像登录凭证的 Cookie 和 localStorage 键，含值）。它和正文在同一个 `chrome.storage.local` 里，没有引入新的暴露面，但**它不是一份「只含元数据」的清单** —— 审计时不要按后者理解。
- **删除可撤销**：索引记录暂放 `pendingUndo`，正文与保护备份保留 6 秒；过期后一起清理。撤销不会自动恢复写回绑定。
- **自动更新必须有明确账号标识**：GitHub `dotcom_user` + `user_session`，B站 `DedeUserID` + `SESSDATA`，X/Twitter `twid` + `auth_token`。只接受站点根域、路径 `/`、Secure、非分区且无歧义的 Cookie。不从语言、设备偏好或旧 learned 规则猜身份。所有自动写入及页面离开写回共用检查、代次和 Cookie 变化计数；尾随 1.5 秒、最长等待 3 秒、单次写回预算 5 秒。
- **Web Storage 只有一个来源文档**：最后一次明确保存、更新或切换的标签页。当前已打开页面立即安装监听；来源页导航后重新授权，其他标签、子框架、旧文档或旧代次不能写回。无法读取时保留旧快照。
- **恢复暂停跨后台重启保留**：恢复后，普通 Cookie 变化不能立即把恢复结果覆盖。需明确更新、切换或重新保存后才重新建立绑定。旧数据首次修改前优先保护旧 `prev`，否则保护当前快照，标注「升级前备份，未验证」。

## 开发

```bash
npm test        # 等价于 node --test
```

单元测试使用 Chrome API 与 DOM 桩。浏览器验收需 Node 22+、空白的隔离 Chrome for Testing，以及加载本目录的扩展：

```bash
agent-browser --session cookie-swap-acceptance --executable-path /path/to/chrome-for-testing --extension "$PWD" open about:blank
# 后续命令沿用相同的 executable-path、extension 或对应环境变量。
agent-browser --session cookie-swap-acceptance get cdp-url
node scripts/browser-acceptance.mjs 'ws://127.0.0.1:PORT/devtools/browser/ID' EXTENSION_ID
agent-browser --session cookie-swap-acceptance close
```

脚本通过真实 cookies/storage/scripting/message API 验证写回、跨账号拒绝、监听幂等、后台终止后恢复暂停等。HTTPS 页面全部被本地响应拦截，只使用虚构账号；它会拒绝已有快照的浏览器，并关闭自己创建的测试标签页。这些测试验证规则与实现，不代表已验证各真实网站当前的登录流程。

## 已知限制

写在这里是因为它们是真的，不是待办清单：

- **只覆盖 Cookie 和 Web Storage。** 登录态放在 IndexedDB、或者是纯内存的 SPA，抓不到 —— 保存时会明确报错而不是静默存一份空的。
- **身份规则不能验证服务器仍接受会话。** 网站修改 Cookie 格式、缺字段或出现歧义时退回手动确认；站点服务器已作废的会话，保护备份也不能复活。不发送保活请求或尝试延长服务端有效期。
- **「页面里有没提交的内容」是启发式检测。** 只看 input / textarea 里值不等于默认值的文本字段；富文本编辑器、纯内存草稿、自定义组件检测不到。检测不到一律不拦（宁可少打扰）。
- **特殊页面用不了。** `chrome://`、扩展页、`file://` 会提示无法读取。
- **切换会刷新页面。** 页面里没提交的内容会丢 —— 检测到时会先问你。
- **所有快照都是可直接登录的会话。** 不要在公用电脑上使用。
